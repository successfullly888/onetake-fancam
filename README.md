# 一键直拍

当前本地构建：`2026.08.25.5`。启动器会从 4173–4183 自动选择空闲端口并打开当前项目，避免旧服务占用 4173 时浏览器继续访问旧后端。

从多人横屏视频中选择一个人物，生成 9:16 动态运镜竖屏直拍，或保持横屏比例、支持分档放大与两侧柔焦的横屏直拍。

当前项目主目录：`D:\codex-一键直拍`。源码、模型、项目私有 Python 依赖和后续开发文件都应保存在该目录；启动与安装脚本使用自身所在位置定位资源，移动后无需修改系统环境变量。

这不是一个“用一句话让 AI 猜目标人物”的工具，而是一个 Human-in-the-loop 的 AI 视频产品：AI 先理解场景，人通过低成本视觉交互确认意图，AI 再完成身份跟踪、镜头规划和视频渲染。

## 当前可运行范围（Milestone 5 主链路 + 场景感知跟踪 V2 + 人工纠正）

- 上传或拖入本地 MP4 / MOV / MKV 视频
- 播放原片并读取真实时长
- 通过双端时间轴掐头去尾
- 生成视频缩略时间轴
- 预览保留片段，或将当前画面设为起点/终点
- 在保留片段内抽取 9 帧，先从整段人数分布推断主要表演者数量，再综合主舞候选、置信度、清晰度、曝光、遮挡与切边评分
- 返回 3 张候选代表帧，允许用户切换画面
- 使用本机 CPU 检测人物；只对最终展示的 3 张代表帧追加高召回舞台分块检测，并用独立编号圆点选择，人物框再大也不会挡住其他人的点击
- 如果目标仍未被 detector 框出，用户可直接点击人物躯干建立人工身份锚点；初始选人和错误帧纠偏都不再依赖“必须先有检测框”
- 合并远处人物被 detector 拆成上半身/下半身的碎片框，并扩展可点击身份区域，避免用残缺裤装框做身份锚点
- 用户点击精确目标，保存帧时间、原画坐标与人物框作为身份锚点
- 对重叠人物不猜测，提示切换更清晰的候选画面
- 从身份锚点向前、向后跟踪同一人物，而不是重新按左右位置猜测
- 分别提取上衣、裤装、亮度结构和低分辨率人体纹理，并把残缺检测框补全为更完整的身份区域
- 同时保留多条候选身份路径，结合固定用户锚点、主舞区角色、运动连续性、框尺寸与 detector 置信度，在看完整段后再决定路径；一帧误判不会立刻污染后半段
- 对短时漏检进行位置预测，并标出低置信、重叠或可能串人的复核区间
- 第一遍身份路径完成后，只对低置信、重叠、异常跳动等风险帧按需运行高召回重检测，再用身份外观重新搜索路径；主舞锚点同时使用舞台景深门控，避免被近景观众或老师抢走
- 纠偏重算返回可审计摘要：人工硬锚点是否全部生效、改变了多少轨迹采样点、锚点帧在复核页中的明确标识；总体置信度不再是唯一反馈
- 已增加可选 SAM 2.1 Small 高精度跟踪内核与 Modal L4 云端部署定义；本地便携版无 GPU 时继续走轻量模式，手机网站部署后默认走视频对象 mask propagation
- 展示真实轨迹抽查帧、检测覆盖率、平均置信度和可靠轨迹比例
- 每张身份复核画面额外运行高召回分块检测，补全远处、举手和遮挡姿态的人物候选；用户可连续暂存多个纠偏点，最后统一重算一次
- 系统保留初始选人点与全部人工锚点，在相邻锚点间分段双向搜索；已经确认的时间点不会被后续纠偏覆盖
- 将稀疏人物轨迹插值并转成平滑镜头轨迹，而不是让裁剪窗逐点抖动
- 提供稳定、自然、灵敏三档镜头响应，以及全身、标准、近景三档人物大小；标准直拍约占画面高度 2/3
- 对镜头轨迹应用中值滤波、双向平滑、dead zone、最大平移速度与加速度约束
- 先把可能残缺的人体检测框推断为完整头脚/动作包络，再生成约 5.5% 头部基础安全空间、标准档约 8% 脚底留白且不出现黑边的 9:16 裁剪窗口
- 先生成 540 × 960 低清预览和 5 张构图抽查帧，再导出 1080 × 1920 H.264 MP4
- 身份跟踪完成后选择“生成竖屏直拍”或“生成横屏直拍”；横屏提供原景 1.00×、适度放大约 1.15×、重点突出约 1.30× 三档，始终保持源视频横屏比例
- 横屏蒙版贯穿画面上下，不包裹人物头顶和脚下；只在人物左右留下约 20% 画宽的清晰呼吸带，再以高斯羽化让两侧其他人物自然柔焦
- 横屏预览最长边限制在 960 × 540 内，高清导出保留原视频分辨率；两种模式均支持预览、音频保留和 MP4 下载
- 原视频包含音频时保留 AAC 音频，并为网页播放启用 faststart

当前主链路已经贯通：上传 → 裁片 → 场景理解 → 选人 → 全片身份路径 → 多帧人工纠偏 → 选择竖屏/横屏直拍 → 预览 → 高清导出。人工纠正会复用首次检测缓存，把多个确认点作为硬约束，只在锚点分段内重新关联身份；不重复执行最耗时的全片 detector。长横屏蒙版路径会压缩为最多 24 个 FFmpeg 表达式关键点，避免长视频因动态表达式过深而生成失败。

## 本地运行

首次使用：

1. 双击 `安装AI能力.cmd`，安装项目私有的 OpenCV 并下载 YOLOv3-tiny 权重。
2. 确保本机可使用 FFmpeg；程序会自动查找项目内的 `tools\ffmpeg\bin`、环境配置、系统 PATH，以及这台电脑现有的 `E:\ffmpeg\bin`。
3. 双击 `启动一键直拍.cmd`，保持命令窗口开启。
4. 浏览器会打开 `http://127.0.0.1:4173`。

两个中文文件是便于识别的入口，内部会分别调用纯英文的 `install-ai.cmd` 与 `start-onetake.cmd`。如果某台 Windows 电脑对中文批处理文件名兼容不佳，可以直接双击对应英文文件，功能完全相同。所有命令脚本均使用 ASCII 内容和 Windows CRLF 换行，避免不同系统代码页把命令截断。

依赖不会写入系统 Python 环境，模型与运行库都保存在项目目录。启动后视频由本机 `127.0.0.1` 服务处理，不上传到云端。

## 最短分发形态

当前继续采用“本地网页工作台 + 本机 Python AI 服务”，而不是重写成桌面 App：浏览器最适合时间轴、视频预览和点击选人，本地服务适合 OpenCV 与后续 FFmpeg 渲染。这条路线没有前端构建链，也不需要云端服务器，最适合短期做出可演示结果。

- 开发/内测：发送完整项目文件夹，接收方首次运行安装脚本，再双击启动脚本。
- 作品集交付：将固定 Python 运行时、依赖、模型、FFmpeg 和启动器打成 Windows 便携文件夹；接收方无需自行安装 Python 或 FFmpeg。
- 当前状态：可以在本机和具备 Python 3.9–3.12 的 Windows 电脑上内测，但还不能称为面向普通用户的最终分发版。

直接双击 `index.html` 只能查看第一阶段界面；人物检测需要通过启动脚本运行本地服务。

> 注意：在 Codex 回复中点击蓝色文件链接通常是查看文件，不会执行 `.cmd`。脚本需要在 Windows 资源管理器里双击。

需要调试时，也可以手动运行：

```powershell
python server.py
```

浏览器打开 `http://127.0.0.1:4173`。

## 最终产品流程

```text
上传视频
  → 裁出保留片段
  → AI 从整段推断主舞人数并挑选“主舞较全且清晰”的代表帧
  → AI 区分主舞候选与周边人物（全部仍可点击）
  → 用户点击一个候选人物
  → 全片身份路径跟踪（向前 + 向后）
  → 用户抽查风险帧；可连续暂存多个正确人物，最后统一应用并重算一次
  → 选择“生成竖屏直拍”或“生成横屏直拍”
  → 竖屏：人物轨迹转自然镜头轨迹，生成 9:16 动态裁剪
    横屏：保持横屏比例分档放大，生成跟随人物的全高中央清晰带与左右柔焦
  → 低清预览并检查构图/柔焦范围
  → 高清导出
```

增强版再加入：基于真实纠偏日志只重算发生变化的更小子区间，并建立带人工真值的多视频身份保持评估集。

## 技术原则

1. 不用 UI 假数据冒充 AI 能力；每个里程碑都可验证。
2. Tracking 不等于 Camera Motion：检测坐标必须经过异常点过滤、平滑、死区和速度约束。
3. 不以“模型永不犯错”为目标；用风险抽查帧暴露不确定性，允许用户暂存多个身份锚点后一次提交。纠错复用检测缓存，只重做锚点之间的低成本身份关联。
4. 每次迭代同时沉淀用户问题、技术决策、指标和可演示证据。
